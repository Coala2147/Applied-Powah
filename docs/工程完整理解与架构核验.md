### 3.3 频道与耗电【已拍板：效仿原版 AE2 + 源码事实】

你要求：**效仿原版 AE2 机制，去读代码**。源码结论如下（【事实】），设计对齐方式为 **【已拍板】效仿该机制**：

**A. 无频道 / 节点不活跃**

- `ChannelPowerSrc.extractAEPower`：节点 `!isActive()` → **返回 0.0**。  
- 即：**无频道时棒不能从 AE 网格抽能**（不是 3–10 AE/t 基础供电）。

**B. 有频道 / 节点活跃时的被动耗电（原版 AE2）**

1. **节点 idle 功耗**（`IGridNode.getIdlePowerUsage` / `IManagedGridNode.setIdlePowerUsage`）  
   - `GridNode`/`ManagedGridNode` **默认 1.0 AE/t**。  
   - 各 part/方块自行设定，例如：线缆、能源元件、Energy Acceptor、Charger 等常为 **0**；指示类 part 常为 **0.5**（灯 **1/16**）；Controller **3**；量子桥 **22**。  
   - 总线类：`UpgradeablePart` 设置 `GridFlags.REQUIRE_CHANNEL`（要频道才能工作）；若不另设 idle，则用节点默认 **1.0 AE/t**。

2. **网络级频道税**（`PathingService`）  
   - `channelPowerUsage = channelsByBlocks / 128.0`（AE/t）。  
   - `EnergyService.getIdlePowerUsage() = drainPerTick + getChannelPowerUsage()`。  
   - 每 tick 按 idle 总量 `extractAEPower(..., PowerMultiplier.CONFIG)` 扣网格电。

**C. 对 AP 充能棒的落地含义【计划，按「效仿」】**

| 场景 | 行为 |
|------|------|
| 节点无频道 / 未激活 | **不**从网络取能（抽能 0） |
| 节点有频道 / 激活 | 可按 §3.2 抽能；同时节点自身应有 **idle 功耗**（是否精确采用默认 1.0 AE/t **【不确定】**，你未指定数字） |
| 网络频道税 | AE2 自动按 `channelsByBlocks/128` 收，**无需 AP 额外实现** |

bus part 的「要频道才工作」= `REQUIRE_CHANNEL` + 默认 idle ≈1 AE/t 的组合，**不是**「缺频道仍有 3–10 AE/t 输出」。

### 3.7 网络风险【已拍板理解】

- 直接抽 AE 可能耗尽网格。  
- ME 侧：**任何吞吐（物品/液体/FE）都会耗 AE 网络能源**；FE 大吞吐会拖垮网络。  
- 输入量大（20M/次、暂 1 tick）时风险更高 → 实现时必须有封顶/安全策略；**具体封顶值【不确定】**。

## 4. refs 关键 API（【事实】，实现引用）

### 4.1 取 AE

`IEnergyService`（extends `IEnergySource`）：  
`extractAEPower(double amt, Actionable mode, PowerMultiplier usePowerMultiplier)`  
范式：`grid.getEnergyService().extractAEPower(amt, Actionable.MODULATE, PowerMultiplier.ONE)`。  
无频道时经 `ChannelPowerSrc` 可得 **0**。

### 4.2 取 ME FE（Applied Flux）

`IStorageService.getInventory().extract(FluxKey.of(EnergyType.FE), amount, Actionable…, source)`  
`NetworkFEPower` 为完整范例；FE 与 AE2 网格 AE 缓冲 **隔离**。

### 4.3 AE2 元件

`EnergyCellBlock(maxPower, chargeRate, priority)`；原版 200000/800/200 与 1600000/1600/1600；致密配方 `CraftingRecipes.java:333` = 8×能源元件 + 运算处理器。  
复用 `EnergyCellBlockEntity` 类时须 **自建 BlockEntityType**。

### 4.4 Part

基类 `AEBasePart`；放置 `PartPlacement`；类名 `ExportBusPart` / `ItemTerminalPart` 等；扳手为 `QuartzWrenchItem` + `WrenchHook` + 标签 `forge:tools/wrench`。  
`UpgradeablePart` → `GridFlags.REQUIRE_CHANNEL`。  
idle 功耗见 §3.3。

### 4.5 Powah 充能台/棒

- Orb：无 FE 电缆口；仅 `fillEnergy`；满 `recipe.getEnergy()` 产出。  
- Rod：`AbstractEnergyStorage`；`postTick` 在 range（默认 4）内有效配方时 `min(存储, transfer)` 推入 Orb。  
- Config 路径：`powah.json5` → `energizing_rods.capacities/transfer_rates`（数值见 §3.2）。  
- `energizing_rod_*` 为 **方块**。

### 4.6 感应卡（对照）

真实语义：使 AE 设备接收/发送能量 + 便携 FE 元件充背包（tick 级），**不是**「周期巨量爆发」源码范本。AP 的「一段时间抽一笔」是 **自有设计**。

### 4.7 AE2 频道配置【事实】

- 默认 `ChannelMode.DEFAULT`：ad-hoc 约 8 频道；线缆容量 factor=1。  
- 本地 `refs/1.20.1/configs/ae2/common.json` 的 `"channels": "infinite"` 是 **你手动改的开发配置**，不能当整合包默认。
